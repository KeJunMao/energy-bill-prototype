# 账单工作台原型

Vite + TypeScript + Faker.js。保留原四页能源账单版式，供产品试用客户、地址、日期及供能账户资料表单。

## 启动

在 `energy-bill-prototype` 目录执行：

```sh
pnpm install
pnpm dev
```

打开终端显示的本地地址（默认 http://127.0.0.1:5173）。

```sh
pnpm build
pnpm test
pnpm preview
```

## 试用

- 编辑称谓、姓名、账户号码、邮寄地址、供能地址，右侧四页账单实时更新。
- 供能地址默认复用邮寄地址，关闭开关后可单独录入。
- 编辑出账日期和计费期；结算期、抄表日期默认联动，也可以单独调整。
- 计费期包含首尾两天；自动抄表区间从开始日到结束日次日。
- “新客户示例”更换客户、邮寄地址及其供能账户资料；日期保持不变。
- “供能资料”页签单独编辑客户的计量点、表号、费率、预计年用量和月度扣款设置。“换固定示例”是显式更换这些资料的入口。
- 预览区“换一组演示数据”仅更换本期账单编号、读数、用量波动、期初余额、热值及推荐报价样例，保留所有已填写资料。
- “保存草稿”保存到当前浏览器 localStorage，包含随机种子，刷新恢复同一份账单。
- “打印 / 导出 PDF”打开四页账单的浏览器打印窗口，目标选择“另存为 PDF”，纸张 A4；如打印界面显示页眉页脚选项，请关闭。
- 切换页面导航或缩放查看明细。窄屏上表单和预览上下排列。

## 原型数据范围

客户、地址、日期及供能账户资料可编辑。供能资料预填一次后保存，只有用户编辑或显式更换客户／固定示例才改变。报表随机种子只控制本期样例。金额计算使用整数十分之一用量和千分之一便士，逐明细舍入到便士后按能源分别计算 5% VAT。

### 第一版从随机数据中拆出的客户资料

| 归属 | 字段 | 何时更新 |
| --- | --- | --- |
| 供能地址 | 电力 MPAN、燃气 MPRN | 更换供能点时 |
| 供能地址 | 轮换区块字母（Rota Block Letter） | 供能点变化或电网信息更新时 |
| 表计 | 电表表号、燃气表表号 | 换表时 |
| 当前计费参数 | 日间／夜间电价、电力固定费、燃气单价／固定费 | 套餐或适用费率变化时 |
| 客户用量评估 | 日间／夜间电力年用量、燃气年用量 | 重新评估时 |
| 付款约定 | 月度 Direct Debit 金额、每月扣款日 | 与客户调整扣款约定时 |

共 15 个字段；这些是当前客户账户保存的资料，并非永远不变。公司、套餐名称／类型、付款方式、税率、价格保证期限、退出费、能源来源表和服务说明仍使用模板配置，没有随机生成，暂不新增编辑项。账单编号、当期读数／用量、期初余额、燃气热值及当期推荐报价继续使用样例；费用、税额、付款汇总和期末余额自动计算。

轮换区块字母用于紧急轮换停电分组，属于供能点资料。有效字母为 A–U，排除 F、I、O（[SP Energy Networks 官方说明](https://www.spenergynetworks.co.uk/pages/rota_load_disconnections.aspx)）。原始文档的 Q 仅作为原客户示例；新客户／新供能资料示例默认留空，由运营根据原账单或 [105 查询](https://www.powercut105.com/findoperator)填写。此字段不会按姓名或账单随机生成，也不会根据城市或 MPAN 地区前缀猜测，更换供能地址后须核对。旧草稿沿用原来显示的字母。

- 初次填入供能资料示例时，年用量按同一户家庭的低、中、高用量档位生成（25% / 60% / 15%），在基准上下 15% 浮动，之后作为表单值保存。基准参考 [Ofgem 2026 TDCV 决定，第 7 页](https://www.ofgem.gov.uk/sites/default/files/2026-05/Review%20of%20typical%20domestic%20consumption%20values%20decision.pdf)：多读数电表年用量 1900 / 3400 / 6100 kWh，燃气 6000 / 9500 / 14000 kWh。初始夜间占比取 35%–45%。
- 电力和燃气分别按合计 100% 的月份权重分配，再按实际日期与月份天数折算；燃气冬高夏低，跨月及闰年都使用同一套规则。本期样例可对月份权重做小幅扰动，全年总用量仍来自同一组保存的年用量。月份权重是原型设定，不是真实天气模型。读数差、燃气转换用量和收费互相对应。
- 初始月度 Direct Debit 示例按电气合计年费 / 12 上下 5% 设定，随后按表单中保存的月扣款金额和 1–28 日扣款日执行。更新费率或年用量不会擅自变更扣款约定；结算期内实际发生的扣款汇总到首页。短账期可能没有扣款，长账期可能有多次扣款，金额为零时不生成扣款记录。
- 期初余额支持结余和欠款；期末余额按期初 + 付款 − 本期费用计算，按正负值展示 CR / DR。欠款余额不等于逾期付款。
- 年费从同一份年用量和费率计算；推荐套餐使用更低的演示单价重新计算年费，节省金额为两份年费的差值。
- 初始 MPAN 示例采用 13 位核心编号和校验位；内置示例城市使用对应的示例区域前缀，其他城市使用模板区域。初始燃气 MPRN 为非零开头的 10 位样例编号。之后从账户表单读取，编辑地址不会自动改写已保存的计量点。手工录入 MPAN 校验位须正确，MPRN 接受 6–10 位数字；示例编号未在真实供能系统中登记。
- 出账日期不早于抄表结束日期；手动抄表区间须与计费天数相同，开始日最多相差一天。结算、计费和抄表区间各支持最长 366 天。

初始费率为原型范围内的模拟值，用户可填入实际适用费率；系统不会自动查询真实价格上限、地区或历史价格。初始日、夜电价一致，可分别修改，明细和年费使用各自费率计算。保存相同草稿可在当前版本中复现同一份报表。旧版草稿加载时保留客户和日期，并补充初始供能资料；更新生成算法后，本期演示值可能变化。

公司信息、套餐名称、服务说明、能源来源表仍沿用模板。每页标有 SAMPLE · PROTOTYPE。

### 套餐二维码

电费和燃气页使用 `qrcode` 库生成可扫描的 SVG 二维码，保留原位置及大小。两个格式独立定义，保持原图中的逗号、空字段及斜杠位置：

```text
电费：{供能邮编},E.ONnext (E.ON Next Energy Limited)/,Next Flex,,Varying,,{MPAN},,None,,{年度日期段}
燃气：{供能邮编},/E.ONnext (E.ON Next Energy Limited),,Next Flex,,Varying,,{MPRN},,{预计燃气年用量},{年度日期段}
```

年度日期段为结算开始日到次年同日，格式 `DDMMYYYY-DDMMYYYY`，闰年 2 月 29 日的次年周年日取 2 月 28 日。生成规则以原图扫码结果为准：原文档结算开始日 `2024-05-27` 对应 `27052024-27052025`。更换供能邮编、演示计量点／年用量或结算开始日后，二维码自动更新。鼠标悬停可查看编码内容，打印 PDF 保留同一个二维码，不依赖外部二维码服务。

原始 `789559486.html` 未改动；原型使用 `src/bill-template.html` 副本。字体和图像在 `public/assets`，运行时不依赖外部资源。表单数据只保存在本机，无服务端、登录或多人共享。

## 文件

- `src/main.ts`：表单交互、预览、草稿保存、打印。
- `src/model.ts`：客户供能资料、本期样例、字段／日期校验及金额计算。
- `src/report.ts`：原模板绑定、地址排版、文本适配。
- `src/tariff-qr.ts`：两套二维码内容格式、年度日期段及 SVG 生成。
- `tests/model.test.ts`：金额一致性、随机复现、日期和必填校验。
- `tests/tariff-qr.test.ts`：原图扫码核对、格式和字段联动、周年日期及编码解码验证。

PowerShell 如果拦截 `pnpm.ps1`，可用 `pnpm.cmd dev`。受限执行环境如临时目录不可访问，可将当前进程的 `TEMP`、`TMP` 指向工作区内的 `tmp` 目录再执行；无需修改系统策略。
